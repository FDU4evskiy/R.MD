# Выдача и возврат

**Пример протокола** · 13 октября 2026

Тема: статусы оборудования, конфликтующие запросы и состав истории операций.

## Решения

| Вопрос              | Решение                                |
| ------------------- | -------------------------------------- |
| Доступные статусы   | `available`, `assigned`, `retired`     |
| Повторная выдача    | Отклонять с HTTP `409`                 |
| Удаление сотрудника | Сохранять его имя в истории            |
| Ошибка при возврате | Показывать причину, форму не закрывать |

## Задачи

- [x] Добавить `retired` в схему и справочник статусов.
- [ ] Backend: проверить статус и создать выдачу в одной транзакции, до 16 октября.
- [ ] Frontend: обновлять карточку после `409`, до 20 октября.
- [ ] QA: проверить две одновременные выдачи, до 21 октября.

## Поля истории

Операция хранит тип, время UTC, идентификатор оборудования, исполнителя и снимок имени сотрудника. Изменение имени в справочнике не переписывает старые операции.

## Открытый вопрос

Нужна ли обязательная причина списания? До решения API принимает необязательное поле `retirementReason`; интерфейс не требует его заполнения.
